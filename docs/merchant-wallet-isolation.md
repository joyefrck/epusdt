# 商户收款地址绑定

本次只修改本地代码，未推送或部署生产。商户对应“支付管理”中的 Key；绑定使用内部 ID，修改商户名称或轮换密钥不改变地址归属。

## 使用方式

- 地址管理列表增加“商户名称”。新增、编辑、批量导入时选择商户，选项显示名称和 PID。
- 同一条链的同一地址只能保存一条归属；一个商户可绑定多个地址。未绑定地址不参与新订单选址。
- 创建订单、收银台首次选币、切换网络均只使用原商户的启用地址。地址不足时返回错误，不从其他商户借用地址。链上扫描继续监控原地址，历史订单仍使用原地址和原商户回调。
- 仪表盘和订单管理原筛选区增加商户选择，默认全部；支持筛选无归属历史订单。仪表盘金额、订单指标、趋势、最近订单随选择变化，链和 RPC 状态属于全局基础设施数据。
- 地址绑定后有过收款订单，不能改绑给其他商户，避免过期款项串入新商户；未使用的地址可以调整归属。旧的未绑定共享地址允许手动分配，但其他商户或无归属的待付款必须先处理完。历史订单的归属始终不随地址绑定变化。

## 升级迁移

启动迁移新增 `wallet_address.api_key_id`（默认 0）和索引，保留原地址唯一约束及已有 MySQL 兼容代码。只有一个未删除 Key，且历史订单没有其他明确商户归属时，自动绑定旧地址。多商户或历史归属有冲突时保留未绑定，管理员从地址编辑中手动选择。

独立迁移标记保证迁移只运行一次，重启不会覆盖之后的人工修改。迁移不重写任何历史订单，不按当前地址归属重新划分历史流水。

## 管理接口

- 地址新增、批量导入传 `api_key_id`；编辑支持该字段及原有备注。
- 地址列表/详情增加 `merchant_name`、`merchant_pid`、`merchant_deleted`；批量查询名称，不返回密钥。
- 订单列表、父子单列表、CSV 和仪表盘各订单数据接口接受 `?api_key_id=内部ID`；不传表示全部，0 表示无归属。空值、负数、非法值及重复参数返回参数错误。
- `GET /admin/api/v1/api-keys?include_deleted=true` 为历史筛选保留删除后的商户名称；新增地址只能选择可用商户。
- 错误码 10047 表示已被其他商户使用的地址不能直接改绑。

## 前端维护

此仓库未包含原 React 前端源码；`sync-www` 工作流从另外配置的私有仓库构建。本次沿用已有组件，对 `src/www/assets/addresses-JEZCoidP.js`、`orders-BnOHTHOA.js`、`dashboard-Cw_CStip.js` 做最小增量，公共选择器源码位于 `src/www/assets/merchant-select.js`；共用表格工具栏增加可选 `extraFilters` 插槽，错误映射增加 10047。未替换导航、页面布局、字体或配色。

`src/www/sw.js` 中六个改动资源使用内容 SHA-256 revision，保证更新后的离线资源可重新加载。将来重建前端时，需要将这些功能同步到对应私有源码仓库，防止 `sync-www` 覆盖。
