# 商户收款地址隔离

用户已确认按此方案直接实现，保留整体页面样式，仅本地开发和验证。

- 商户对应支付管理中的 API Key，地址以 `api_key_id` 绑定内部 ID；更名、轮换 secret 不改变归属。同一链的同一地址维持全局唯一，不能同时分配给多个商户。
- 创建订单、收银台首次选币、切换网络三个路径均仅选择所属商户启用的地址。未绑定地址不参与新订单，不回退全局池。已有订单继续按自身存储的地址和商户匹配、回调。
- 地址管理列表新增商户名称列；新增、编辑、批量导入增加商户选择，名称相同时可通过 PID 区分。旧地址明确显示未绑定；已删除商户仍能识别原 ID，不变成共享地址。
- 仪表盘、订单管理在已有筛选区新增商户下拉，默认全部商户。仪表盘订单指标、趋势、最近订单采用同一商户条件；RPC 健康/链状态仍为全局基础设施指标。订单导出遵循同一筛选。
- 旧地址迁移仅在恰好一个未删除商户且没有其他商户历史归属冲突时自动绑定；多商户或冲突场景保留未绑定并由管理员分配。迁移只运行一次，重启不得重新将管理员取消绑定的地址绑定。历史订单的 `api_key_id` 不重写。
- 正在收款的地址不可改绑，以免新旧订单混淆。历史未绑定且曾共享的地址可在其他商户待付款完成后手动指定归属，不重写历史订单。已绑定并使用的地址跨商户转移须拒绝，使用新地址实现隔离，避免过期订单延迟到账产生跨商户歧义。商户删除/禁用后该地址不再分配给新订单。
- 保留现有 MySQL/SQLite/PostgreSQL 兼容代码、原有未提交改动和页面组件样式。仓库仅有前端构建产物，优先寻找对应源码；无法取得时维护最小产物变更并记录位置与缓存更新方式。

验收包括：两个商户相同金额不同地址、未绑定地址无法被选中、首次选币和切换链隔离、单商户迁移幂等与多商户不迁移、地址管理字段及非法商户校验、仪表盘全指标/趋势/最近订单筛选、订单分页及导出筛选、历史订单回调归属、桌面及窄屏页面视觉检查。
