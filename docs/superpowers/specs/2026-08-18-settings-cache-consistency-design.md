# 设置页缓存一致性修复设计

## 问题与证据

系统设置页保存后会先显示成功提示，再调用对应 Settings 查询的 `refetch()`。如果用户在刷新完成前切换菜单，查询会随组件卸载被取消；全局 React Query 的 `staleTime` 为 10 秒，短时间返回页面时会继续用旧缓存回填表单。

生产现场已经确认：公开配置接口返回已保存的 `ethereum`，菜单切回仍显示旧的 `TRON`，强制刷新并等待接口完成后显示 `Ethereum`。因此后端持久化正常，缺陷位于前端共享 Settings 查询生命周期。

## 范围

共享查询同时服务以下页面，必须统一修复：

- 基础配置（`brand`）
- Telegram 配置（`system`）
- 系统日志（`system`）
- 支付配置（`system`、`rate`）
- EPay 配置（`epay`）
- OkPay 配置（`okpay`）

不修改后端 Settings 持久化、业务配置解析或数据库结构。

## 设计

在共享 Settings 查询上设置：

- `staleTime: 0`：配置数据读取后立即视为可重新校验。
- `refetchOnMount: "always"`：每次进入设置页面都读取服务端权威值。
- `gcTime: 0`：最后一个观察者卸载后不保留旧分组缓存，避免取消中的刷新回退到旧数据。

保留各页面保存后的显式 `refetch()`，因此停留当前页面时仍会立即同步；快速切页后重新进入则由共享策略重新拉取。

当前仓库只包含前端构建产物，修改共享 `lib-*.js` 后，需要给 Service Worker 预缓存条目设置新的显式 revision，确保已安装旧 Service Worker 的浏览器重新获取同名资源。

## 验证

新增 Go 回归测试扫描随二进制发布的前端构建资源，验证共享 Settings 查询包含三项策略，并验证 Service Worker 对该资源使用与内容一致的显式 SHA-256 revision。生产验收覆盖：保存配置、立即切换菜单、返回页面、确认显示服务端最新值。
