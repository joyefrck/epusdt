# 统一支付默认配置与重复切换设计

## 背景与目标

生产订单已经证明，后台保存的 `epay.default_token`、`epay.default_network` 和 `epay.default_currency` 只在 EPay `submit.php` 参数缺省时生效；GMPay 会直接采用调用方请求值。GateRank 又固定发送 `USDT/TRON/CNY`，导致后台默认网络改成 Ethereum 后，新订单仍按 TRON 创建。

收银台还存在一个独立但相关的问题：具体父订单第一次切换支付目标后，后端创建子订单，前端跳转到子订单页面。子订单的 `is_selected=true` 会隐藏“切换网络或币种”按钮，后端也明确拒绝使用子订单再次调用 `/pay/switch-network`，并且每个父订单最多只能创建一个子订单。

本次改动目标：

1. 所有初始订单都强制采用 Epusdt 后台保存的默认代币、网络和法币，不允许调用方请求覆盖。
2. GateRank 不再发送写死的支付资产参数，由 Epusdt 决定初始支付目标。
3. 付款人仍可在收银台主动切换网络、代币或 OkPay。
4. 第一次切换后仍能继续切换；相同支付目标复用现有等待支付子订单，不同支付目标创建独立子订单。
5. 任一父订单或子订单付款成功后，只回调一次商户，并终止其余等待支付目标。

## 行为规则

### 初始订单强制使用全局默认值

GMPay 和 EPay 订单在签名验证完成后、业务参数校验和落库之前，统一执行默认配置解析：

- `token` 始终取 `epay.default_token`。
- `network` 始终取 `epay.default_network`。
- `currency` 始终取 `epay.default_currency`；为空时保持现有 `cny` 兜底。
- 调用方提交的 `token`、`network`、`currency` 仍参与其原始请求的签名校验，但不参与订单资产选择。
- 默认 `token` 和 `network` 同时为空时，沿用现有 status=4 等待付款人选择流程。
- 默认 `token` 和 `network` 只有一个为空时，返回稳定的参数错误，不创建不完整订单。
- 默认配置指向未启用网络、未启用资产、无钱包地址或无汇率时，沿用现有稳定业务错误，不自动回退到请求参数。

EPay 的 `type` 参数仍按现有协议参与签名和合法性校验，但不能覆盖全局默认支付资产。为了避免回调报告的支付类型与实际链上资产不一致，具体订单落库的 `epay_type` 使用最终默认资产生成的 `token.network`；status=4 占位订单保留空值，待用户选择后再写入实际目标。若订单最终通过切换后的子订单完成，父订单结算事务同时把 `epay_type` 更新为实际支付子订单的 `token.network`，通知和浏览器回跳都以该最终值签名。

默认配置只决定初始订单。付款人通过 `/pay/switch-network` 主动选择后，以付款人的选择为准，不再强制改回后台默认值。

### GateRank 调用调整

GateRank 的 USDT/GMPay 创建请求删除写死的 `currency`、`token` 和 `network`。签名只覆盖实际发送字段。Epusdt 的创建请求校验允许这三个字段缺省，并在验证签名后注入后台默认配置。

GateRank 的通知验签继续对 Epusdt 实际回调字段进行签名验证，不假定网络必须为 TRON。现有订单、历史通知和查询结果不迁移。

## 重复切换模型

### 根订单识别

`/pay/switch-network` 接受父订单或其任一子订单的 `trade_id`：

- 请求是父订单时，直接以该订单作为根订单。
- 请求是子订单时，通过 `parent_trade_id` 加载根订单。
- 根订单必须仍为等待支付或等待选择状态；已支付、已过期或不存在时返回现有稳定错误。
- 子订单本身已过期时，收银台不会显示切换入口；后端仍以根订单状态作为最终一致性校验。

### 子订单创建与复用

- 切回根订单自身的 `token/network` 时，返回根订单。
- 已存在相同 `token/network` 的等待支付链上子订单时，复用该子订单。
- 已存在相同 token 的等待支付 OkPay 子订单时，复用其已有支付链接。
- 切换到新的目标时创建新的子订单，不再限制父订单一生只能有一个子订单。
- 不覆盖或复活已过期子订单，避免旧收款地址晚到账时失去审计记录。
- 同一目标的等待支付子订单只保留一条；全局创建锁继续防止并发重复创建。
- 多个等待支付目标可以同时存在，因此付款人向之前展示过的地址付款仍可被识别。

现有结算逻辑已经支持多个兄弟子订单：任一子订单支付成功后标记父订单成功，其他等待支付子订单失效并释放运行时地址锁；父订单直接付款成功时同样终止全部子订单。本次保留并补充该行为的回归覆盖。EPay 父订单由子订单结算时，在标记成功的同一事务内记录实际支付目标对应的 `epay_type`，避免通知读取到初始默认目标。

### 收银台状态

`CheckoutCounterResponse` 增加 `parent_trade_id`。前端按以下规则确定根订单：

- 父订单响应使用自身 `trade_id`。
- 子订单响应使用 `parent_trade_id`。

切换接口始终提交根订单 ID；后端仍支持传入子订单 ID，作为兼容和防御性处理。支付状态轮询使用根订单 ID，保证用户正在查看第二或后续子订单时，如果父订单通过任一目标完成，也能进入成功状态。

等待支付的链上父订单或子订单只要存在可用支付选项，就始终显示“切换网络或币种”。按钮显示不再依赖 `is_selected=false`。切换成功后可以继续导航到返回的具体订单 URL，刷新页面后通过 `parent_trade_id` 恢复根订单上下文。

## 数据与兼容性

- 不新增数据库表或字段；复用现有 `orders.parent_trade_id`、`pay_by_sub_id`、`is_selected` 和子订单结算逻辑。
- 不改写历史订单。
- Epusdt API 的行为变化是有意的破坏性调整：创建请求中的资产字段不再控制初始支付目标。
- EPay 回调的 `type` 改为反映实际默认或最终完成支付的用户选择资产；该值与父订单成功状态在同一事务内写入，避免回调与真实链不一致。
- 保留现有签名算法和密钥格式；强制默认值发生在签名验证之后。
- 保留商户回调只由父订单触发的约束，子订单不单独回调。

## 错误处理与资源安全

- 默认配置不完整、网络禁用、资产禁用、汇率缺失、钱包不足均返回现有业务错误，且不创建订单。
- 创建子订单失败时释放本次预留的运行时地址锁。
- 重复切换到现有目标不重复预留地址、不重复创建 OkPay 订单。
- 多目标支付完成后，继续验证兄弟链上地址锁释放和兄弟 OkPay 订单失效。
- 不删除旧子订单，保留审计和晚到账排查能力。

## 测试方案

### Epusdt

新增或调整测试覆盖：

1. GMPay 显式提交 TRON，但后台默认 Ethereum，最终订单为默认 Ethereum。
2. EPay `type=usdt.tron`，但后台默认 Ethereum，最终订单和回调类型均反映默认 Ethereum。
3. 创建请求省略资产字段仍能使用默认配置。
4. 默认资产同时为空时创建 status=4 占位订单；默认只缺一项时拒绝创建。
5. 从父订单连续切换到两个不同目标，分别创建并返回两个子订单。
6. 使用第一个或第二个子订单 ID 再次切换，后端正确解析根订单。
7. 重复选择相同目标复用已有等待支付子订单。
8. 从子订单切回父订单默认目标返回父订单。
9. 多子订单中的任意一个支付成功后，父订单成功、其他子订单失效、运行时锁释放且只产生一次商户回调；EPay 父订单回调类型反映实际付款子订单。
10. 收银台构建产物包含 `parent_trade_id` 根订单处理，并且具体子订单仍显示切换按钮。

### GateRank

调整支付网关服务测试，验证创建请求和 HMAC 签名均不包含写死的 `currency`、`token`、`network`，并验证 Ethereum 等非 TRON 回调仍可通过签名校验。

## 非目标

- 不禁止付款人主动切换支付目标。
- 不改变汇率计算、钱包选择、链上扫描或 OkPay 对接规则。
- 不为每个 GateRank 业务单独增加支付网络配置。
- 不迁移或重新生成已创建订单。
- 本设计不自动授权生产发布；代码验证完成后单独报告可发布范围。
